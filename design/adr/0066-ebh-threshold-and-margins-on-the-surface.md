# ADR 0066 — e-BH threshold and per-leaf log-margins on the fleet surface (engine ADR 0027 adoption)

- **Status:** ACCEPTED (measured below)
- **Date:** 2026-09-02
- **Decision owner:** Tessera-RNG (knowledge WORKLIST C60 item 4)
- **Relates to:** engine ADR 0027 (the fields this consumes), ADR-0065 (the exact `log_e_value`
  record this reads; its "selection stays on linear e-BH" anti-scope is REVISITED below on new
  evidence), ADR-0050 (the dispersion boundary — unchanged), ADR-0060 (the FDR license — unchanged),
  `knowledge/stats/pages/e-betting-metrics-2026-09-02.md` option 3, Ramdas–Wang 2025
  Proposition 9.12.

---

## What the engine pin brings

Engine v0.6.8-pre (`fleet/e-bh.ts`): both e-BH variants return `{ selected, K, log_threshold_e,
log_margin }`. `log_threshold_e = log(N/(q·max(K,1)))` separates the selected set exactly —
`selected` is precisely the indices with `log_margin ≥ 0` (proof in the engine field docstring;
Ramdas–Wang 2025 Prop. 9.12: e-BH rejects iff `e_k ≥ t_q`, `t_q ∈ {N/(kq)}`). A zero e-value's
margin is floored at `−LOG_MAX_WEALTH`, never `−Infinity`. Before this ADR `buildSurface` read
only `selected`.

## Decision

1. **`FleetSurface` gains `log_threshold_e: number` and `margins: ReadonlyArray<{ path_class_id,
   log_margin }>`** (canonical id order, aligned with the audit's `verdicts`). The audit record
   carries both at top level next to `selected_path_class_ids`. Additive; nothing else on the
   surface or audit changes bytes.
2. **DIAGNOSTIC, NOT A GUARANTEE.** The threshold is data-dependent (it moves with K); a margin
   ≥ 0 means selected in THIS snapshot, a negative margin is a distance under a threshold that
   would itself move if the leaf's evidence did. The FDR claim is unchanged and still rests on
   the inputs being e-values: ADR-0050's dispersion boundary and the ADR-0060 license gate apply
   to the reading of these fields exactly as to the selection. The docstrings say so where the
   fields are.
3. **Selection input: the log variant when every verdict carries `log_e_value`; the linear
   variant otherwise (pre-ADR-0065 audits); never mixed within one call.** This revisits
   ADR-0065's anti-scope, which kept linear selection because switching "would move selections
   at ulp boundaries for zero measured gain". The gain is now measurable: with the linear variant
   the margins of saturated leaves tie (all at `log(MAX_VALUE) − threshold`); with the log variant
   they carry the exact record. Measured before switching (`selected` compared byte-for-byte,
   linear vs log, on every committed fixture):
   - all 8 demo scenarios (N=300; K = 0, 17, 31, 19, 0, 78, 31, 31): identical; max
     |Δ log_margin| ≤ 1.4e-14 (ulp-level, from `log(e_value)` vs `log_e_value`);
   - the ADR-0065 δ=32 saturation run (N=109, K=88, 10 saturated leaves): identical selection;
     max |Δ log_margin| = 3844 nats — entirely on the saturated leaves, where the linear margin
     is the tied cap and the log margin is the true magnitude;
   - 10 Spraypoint runs (5 seeds × clean / optic-3 δ=4): identical.
   The ulp-boundary risk ADR-0065 named remains in principle (a leaf within ~1e-14 nats of the
   threshold could flip) and was not observed on any fixture. The committed demo's selections,
   `fleet_log_e`, culprits and drains are byte-identical after the switch (AC-3).
4. **The demo payload drops `margins`** on the same grounds it already drops `verdicts` (the page
   renders neither; ~8×300 rows would multiply a 15 KB file). `log_threshold_e` is embedded.

## Anti-scope

- No renderer for the margins in the demo or the drill-down; no ranking or sorting by margin
  anywhere. The field is recorded for operators and downstream readers, not consumed.
- `fleet_log_e` keeps its ADR-0065 computation (linear views, floored) — unchanged bytes.
- No engine ADR 0027 `DetectorVerdict.evidence` surface, calibration monitor, or mixture CS
  adopted here; the per-detector RNG results keep their shape.
- No STATE.md round entry; this is a single additive field pair under an existing pin.

## Acceptance criteria

- **AC-1 (sign ⇔ selection):** `margins.filter(≥ 0)` equals `selected_path_class_ids` on the
  existing fixtures, on 200 random linear snapshots and 200 random log-domain snapshots (with
  ties and zeros), on a firing pipeline run, and on the δ=32 saturation run.
- **AC-2 (threshold formula):** `log_threshold_e = log(N/(q·max(K,1)))` within 1e-12 relative
  (the log variant computes `log(N/q) − log(max(K,1))`, an ulp apart from the linear form).
- **AC-3 (bytes):** every committed fixture's `selected` is identical between variants (above);
  `demos/demo.html` regenerated by `pnpm demo` differs from its predecessor only by the eight
  embedded `log_threshold_e` scalars.
- **AC-4 (JSON-safe):** a surface with saturated leaves and a zero e-value round-trips through
  JSON with no `null` and no `Infinity`; the zero leaf's margin is exactly
  `−log(Number.MAX_VALUE)` under both variants.
- **AC-5 (saturation ordering):** on the δ=32 run the saturated leaves' margins are strictly
  ordered (the log variant's record), where the linear view ties.
- **AC-6 (no mixing):** a verdict set with `log_e_value` on some leaves only takes the linear
  procedure whole and selects as before.
- **AC-7 (suite):** full suite green (327 → 334).
